# hammieboye-bot

명령어 기반 응답 + OpenAI API 자연어 폴백을 제공하는 디스코드 챗봇입니다.

## 기능

- 채널 상관없이, 허용된 서버(길드)라면 어디서든 메시지 맨 앞을 정해진 "호출 단어"로 시작하면 응답합니다. 호출 단어는 `.env`의 `CALL_PREFIXES`에서 지정하며(예: `해미야,햄이야,햄스터야,해미보이야,햄아`), 이 값이 없으면 봇이 실행되지 않습니다.
  - 예: `해미야 안녕` -> `해미야`를 정확히 뗀 뒤 `안녕`만 봇에게 전달
  - 호출 단어로 시작하지 않는 일반 메시지에는 전혀 반응하지 않습니다 (부분 일치가 아니라 문자열 맨 앞부분이 완전히 일치해야 함)
- 허용된 서버는 `ALLOWED_GUILD_IDS`로 지정하며, 목록에 없는 서버에서는 호출 단어를 불러도 무시됩니다.
- 호출 단어를 뗀 나머지 텍스트는 다음 순서로 처리됩니다:
  1. **명령어**: `command_registry.py`에 등록된 명령어의 별칭(alias)과 정확히 일치하면 그 명령어의 응답을 반환합니다. 공백과 대소문자는 무시하고 비교합니다 (예: `플라스틱 병`, `플라스틱병`, `페트병` 모두 같은 명령어로 인식).
  2. **자연어**: 어떤 명령어와도 일치하지 않으면 OpenAI API(`gpt-5-nano`, 가장 저렴한 모델)를 호출해 답변을 생성합니다.
- **최초 사용자는 온보딩을 먼저 통과해야 합니다.** 처음 호출 단어로 봇을 부르면 채널에 데이터 수집 안내가 올라오고, `해미야 동의`라고 말해야 그 이후부터 명령어/자연어 응답이 동작합니다. 동의 전까지는 채팅 횟수도 늘지 않습니다.
- **자연어 메시지에는 호감도 시스템이 적용됩니다** (`core/chat.py`):
  - 호감도가 음수면 OpenAI를 아예 호출하지 않고 `(무시)`(-1~-19) 또는 `(콱 깨묾)`(-20 이하) 고정 응답만 돌려줍니다.
  - 분당 자연어 10회를 넘기거나, 같은 말을 히스토리(30분/최대 50개) 내에서 3번 넘게 반복하면 그다음 호출부터 호감도가 -1씩 깎입니다.
  - 대화 내용은 이전 대화와 무관하게 매번 독립적으로 생성되지만(맥락 기억 없음), 위 판정을 위한 최근 30분 히스토리는 Supabase `chat_history`에 별도로 남습니다.
- **`페트병` / `플라스틱 병` / `플라스틱`이라고 부르면 병 던지기 게임을 합니다** (`command/plastic/plastic.py`):
  - 50% 확률로 성공(잡고 춤), 실패하면 10분 쿨타임이 시작됩니다 (성공 시에는 쿨타임 없이 바로 또 던질 수 있음).
  - 쿨타임 중에 또 부르면 쿨타임 메시지만 돌아오고, 이 메시지를 4번째 유발하는 순간부터 호감도가 -1씩 깎입니다 (남용 방지).
  - 첫 성공 시 호감도 +1(하루 1번), 연속 3회 성공 시 보너스로 +3(하루 1번) — 이 명령어로 하루에 얻을 수 있는 최대 호감도는 4입니다.
- **자연어 답변마다 Hammie의 감정도 함께 판정됩니다** (긍정 10개/부정 10개 ENUM, `responses/engine.py`의 judge 호출에 얹어서 처리 — API 호출을 추가로 늘리지 않음):
  - 감정이 정확히 `행복함`이면 호감도 +1 (하루 1번)
  - 부정적 감정이 연속 2회 또는 하루 5회 이상 나온 뒤, 그다음 부정적 감정부터 호감도 -1씩. 긍정적 감정이 나오면 연속 카운트만 리셋되고(일일 누적은 유지) 페널티 자체는 없습니다.
- **하루 정확히 5번, Hammie가 먼저 말을 겁니다** (부름 이벤트, `core/call_event.py`):
  - 매일 06:30(KST)에 그날 09:00~21:00 사이 5개 시각을 한 번에 미리 정해두고(`core/scheduler.random_times_in_window`), 그 시각이 되면 등록된 모든 서버에 동시에 "배고파", "심심해" 류 메시지를 올립니다.
  - 각 서버의 **가장 최근에 봇이 호출된 채널**에 올라갑니다 (별도 설정 불필요, 자동 기억).
  - 자연어로 가장 먼저 "상황에 맞게" 반응한 사용자 1명(전체 서버 통틀어)에게 호감도 1~10 랜덤 지급 — 관련성 판정은 `OPENAI_JUDGE_MODEL`로 별도 LLM 호출 1회 (하루 5번뿐이라 비용 부담이 적어 상위 모델 사용). 호감도가 음수인 사용자도 이 이벤트만은 예외적으로 참여할 수 있습니다.
  - 다른 서버가 먼저 반응했다면 나머지 서버의 원본 메시지에 "`(○○ 서버의 ○○가 해줬어!)`"를 덧붙입니다.
  - "가서 혼자 놀아"처럼 부정적으로 반응하면 호감도 -5.
  - 게시 후 10분 동안 어느 서버에서도 반응이 없으면 등록된 모든 사용자의 호감도가 -1 (`apply_global_penalty` RPC로 한 번에 처리).
- **매일 23:59(KST), 그날 가장 많이 대화한 사용자를 언급합니다** (취침 이벤트, `core/sleep_event.py`):
  - 당일 순증감(`daily_net`)이 음수인 사용자는 후보에서 제외, 동률이면 동률자 전원에게 호감도 +1.
  - 대화한 사람이 아예 없거나 후보가 전부 제외됐다면 등록된 사용자 중 무작위로 1명에게 지급.
- **취침 시간(00:00~06:30 KST)에는 무슨 일이 있어도 응답하지 않습니다** (`core/scheduler.is_sleep_time`, `core/dispatcher.py`의 `on_message` 맨 앞에서 체크). 명령어/자연어/온보딩 전부 포함이며, 채팅 횟수 집계 같은 부수 효과도 전혀 안 일어납니다. 유일한 예외는 봇을 맨션(`@Hammie`)한 경우로, 아래 취침 중 맨션 깨움 이벤트만 발동할 수 있습니다.
- **취침 중 맨션을 계속하면 Hammie가 깨어납니다** (`core/wake_event.py`):
  - 메시지 1개 = 맨션 횟수 1회(한 메시지 안에서 여러 번 연속 맨션해도 1회). 서버마다 그날 밤 새로 뽑힌 랜덤 임계치(1~10회)에 도달하면, 그 서버에서 딱 1번만 깨움 이벤트가 발동합니다.
  - 90% 확률로 "짜증"(고정 대사, 호감도 -5), 10% 확률로 "악몽 감사"(고정 대사, 호감도 +5). **이 +5는 하루 +20 획득 상한에 포함되지 않습니다** (`add_affection_uncapped` RPC 사용).
  - 발동 후 그 밤 동안은 같은 서버에서 추가 맨션에 반응하지 않고(방해금지), 커스텀 상태도 "누가 깨웠어... 방해금지 🚫" + Discord DND로 바뀝니다. 단, 이 카운트/1회 제한 로직 자체는 서버마다 독립이지만, 상태 표시(presence)는 봇 계정 전체에 하나뿐이라 다음 기상(06:30)까지 전역으로 유지됩니다.
- **취침/기상에 맞춰 디스코드 상태가 바뀝니다** (`core/presence.py`): 00:00엔 자리비움(idle) + "쿨쿨... 잠자는 중 🌙", 06:30엔 온라인 + "페트병 흔드는 중 🐹". 봇이 취침 시간대 도중에 켜져도 시작하자마자 현재 상태에 맞춰 즉시 전환됩니다.
- **매일 06:30(KST), 아침 인사 + 생일 카운트 + 기념일을 말합니다** (`core/greeting.py`):
  - "태어난 지 N일째"(생일 2017-12-22 기준)를 매일 다른 표현으로 생성 — 하루 1번뿐이라 `OPENAI_JUDGE_MODEL` + `reasoning.effort="low"`로 더 자연스럽게 생성합니다.
  - 오늘이 특별한 날인지는 **LLM 판단에 맡기지 않고 Python 코드가 날짜로 직접 확정**해서 프롬프트에 명시적으로 지시를 주입합니다 (생일이면 "오늘은 당신의 생일입니다. 축하해달라는 메시지를 추가하세요" 같은 식).
  - 기념일 32개(양력 고정 23개 + 음력/계산 기반 9개: 설날·정월대보름·부처님오신날·추석·수능날)를 지원하며, 음력 변환은 `korean_lunar_calendar` 패키지를 씁니다. 여러 기념일이 겹치면 전부 언급합니다.
- **누구에게 하는 말인지 명확하도록 항상 답장(reply)으로 응답합니다.** 봇이 스스로 먼저 말 거는 부름/취침/아침 인사만 예외로 일반 메시지입니다.
- **호감도가 실제로 바뀔 때마다 하트 이모지와 함께 알려줍니다**: 💕(상승)/💔(하락) + 증감량 + 현재 호감도를 응답 끝에 덧붙입니다. 한 메시지에서 여러 증감이 겹쳐도(예: 과호출 페널티 + 감정 보너스) 합산해서 한 번만 표시합니다. 정보 embed에는 이미 호감도가 보이므로 따로 안 붙습니다.
- **"너 누구야?" 같은 자연어에는 고정 자기소개**로 답합니다 (`core/intent.py`의 `SELF_INTRO`, LLM 생성 없이 즉시 응답).
- **새 고정 명령어 2개**:
  - `도움`/`헬프`/`명령어`/`리스트` → 등록된 명령어 목록
  - `나`/`정보`/`호감도` → 호감도/채팅 횟수/도와준 횟수/오늘 대화 횟수/최근 대화를 **연주황색 embed**로 표시
- **자연어도 의도가 맞으면 고정 명령어/캐시 응답으로 리다이렉트됩니다**: `core/intent.py`가 저렴한 `OPENAI_MODEL`(nano)로 `help`/`info`/`self_intro`/`none`을 분류합니다. 전체 처리 우선순위는 다음과 같습니다.
  1. 고정 명령어 (별칭 완전일치)
  2. 자연어 → 고정 명령어 (`help`/`info` 의도)
  3. 자연어 → 프롬프트 캐시 (`self_intro` 의도, LLM 생성 없음)
  4. 자연어 → 자연어 생성 (그 외 전부, 음수 호감도 게이트 적용)

## 구조

```
hammieboye-bot/
├── main.py                    # 진입점. client 생성 + dispatcher 연결 + 실행/종료만 담당 (로직 없음)
├── config.py                  # 환경 변수 로드 (.env)
├── command_registry.py        # 명령어별 별칭(prefix) 목록 + 어떤 handler를 쓸지 한 곳에서 관리
├── core/
│   ├── client.py               # discord.Client 생성 (intents 설정)
│   ├── dispatcher.py           # on_ready/on_message 이벤트: 호출 단어 -> 동의 게이트 -> 명령어 매칭 -> 자연어 폴백, 백그라운드 태스크 부트스트랩
│   ├── onboarding.py           # 최초 사용자 동의 안내 문구 + 동의 문구 판정
│   ├── chat.py                 # 자연어 턴 파이프라인: 과호출/반복 감지 -> 부름 이벤트 응답 체크 -> 음수 호감도 게이트 -> 자연어 응답 -> 감정 반영
│   ├── scheduler.py            # 매일 KST 특정 시각 / 일정 간격으로 실행되는 백그라운드 태스크 등록
│   ├── call_event.py           # 부름 이벤트: 하루 5개 시각 산출, 게시, 클레임/부정반응 판정, 무응답 페널티
│   ├── sleep_event.py          # 취침 이벤트: 매일 23:59 최다 대화자 언급 + 보상
│   ├── greeting.py             # 매일 06:30 아침 인사 + 생일 카운트 + 기념일(양력/음력) 언급
│   ├── intent.py               # 자연어 -> 고정 명령어/프롬프트 캐시 라우팅 분류 + 자기소개 텍스트
│   ├── presence.py             # 취침(00:00 idle)/기상(06:30 online)/깨움 이벤트(dnd) 디스코드 상태·커스텀 상태 전환
│   └── wake_event.py           # 취침 중 맨션 깨움 이벤트: 서버별 맨션 카운트/임계치 판정 + 짜증·악몽 반응
├── db/
│   ├── client.py                # Supabase REST/RPC 저수준 래퍼 (aiohttp)
│   ├── users.py                 # 사용자 조회/생성/동의/채팅 횟수 증가/병 던지기 쿨타임
│   ├── history.py               # 채팅 히스토리 기록/조회 (30분/최대 50개 범위)
│   ├── affection.py             # 호감도 증감 RPC 래퍼 (일일 +20 상한은 DB 함수가 처리, 상한 미적용 버전과 전체 유저 일괄 증감도 포함)
│   ├── daily_stats.py           # 오늘(KST) 구간 데이터 조회/생성/갱신 (연속 성공, 쿨타임 남용, 오늘 대화 횟수 등)
│   ├── guild_channels.py        # 서버별 "마지막 활동 채널" 기록/조회 (부름/취침 이벤트가 올릴 채널 결정용)
│   ├── guild_sleep_state.py     # 취침 중 맨션 깨움 이벤트: 서버별 임계치/카운트 원자적 등록 (RPC 래퍼)
│   └── call_events.py           # 부름 이벤트 스케줄/게시/클레임 CRUD
├── command/
│   ├── base.py                  # 공용 Command 데이터클래스 + 별칭 정규화(normalize) 함수 + embed 시그니처 컬러
│   ├── plastic/plastic.py       # 병 던지기 게임 (쿨타임/연속성공/일일 획득 상한 로직)
│   ├── help/help.py             # 명령어 목록 안내
│   └── info/info.py             # 내 정보/호감도 embed
├── responses/
│   └── engine.py               # 자연어 폴백 처리 (OpenAI Responses API 호출 + LLM-as-judge 검수)
├── supabase/
│   └── schema.sql              # Supabase SQL Editor에 실행할 DDL (테이블 + RPC 함수)
├── requirements.txt
└── .env.example
```

**설정과 실행 코드 분리**: 명령어의 별칭(prefix) 목록은 전부 `command_registry.py` 한 파일에 모여 있고, 각 명령어의 실제 실행 코드는 `command/<이름>/<이름>.py`에 `handle()` 함수 하나로만 존재합니다. 별칭을 바꾸거나 새 별칭을 추가할 때는 실행 파일을 건드릴 필요 없이 `command_registry.py`만 수정하면 됩니다.

**메시지 처리 파이프라인과 백그라운드 이벤트는 `core/` 아래로 모아둡니다**: `dispatcher.py`(라우팅) → `onboarding.py`(동의 게이트) → `chat.py`(자연어 턴 처리) 순서로, 전부 "메시지를 어떻게 처리할지"를 다루는 orchestration 계층이라 한 폴더에 둡니다. `call_event.py`/`sleep_event.py`도 봇이 스스로 먼저 행동하는 로직이라 같은 계층으로 취급합니다. `dispatcher.py`의 `on_ready`에서 `call_event.init`/`sleep_event.init` + `scheduler.start_daily`/`start_interval`을 한 번만 호출해 백그라운드 태스크를 부트스트랩합니다 (재연결로 `on_ready`가 다시 불려도 중복 시작되지 않게 가드함). 루트에는 진입점(`main.py`)과 설정(`config.py`, `command_registry.py`)만 남깁니다.

   - `OPENAI_MAX_OUTPUT_TOKENS`: 예 `120`. gpt-5-nano는 reasoning 토큰도 같은 예산을 쓰므로(코드에서 `reasoning.effort=minimal`로 최소화해둠) 너무 낮으면 답변이 중간에 잘릴 수 있습니다
   - `OPENAI_PROMPT_CACHE_KEY`: 예 `hammieboye-chat-v3` (아래 프롬프트 캐싱 참고)
   - `SUPABASE_URL`: Supabase 프로젝트 URL (대시보드 > Project Settings > Data API)
   - `SUPABASE_SERVICE_ROLE_KEY`: Supabase service_role 키 (같은 화면). RLS를 우회하는 강력한 키이므로 절대 커밋/클라이언트 노출 금지

## 새 명령어 추가하기

1. `command/` 아래 명령어 이름으로 폴더를 하나 만들고, 그 안에 실행 파일 하나만 둡니다 (예: `command/glass/glass.py`). 이 파일에는 `handle(user_id: int) -> str | discord.Embed`(실행 로직)만 작성하고, 별칭은 넣지 않습니다. `user_id`는 DB 조회/갱신이 필요 없는 단순 명령어라면 안 써도 됩니다. 시스템 형태 정보(호감도/횟수 등)를 보여줄 땐 `discord.Embed(color=command.base.EMBED_COLOR)`로 반환하세요 (`command/info/info.py` 참고).

   ```python
   async def handle(user_id: int) -> str:
       return "유리병은 이물질을 제거하고 헹궈서 배출해주세요 🍾"
   ```

2. `command_registry.py`에서 그 `handle`을 import하고, 별칭(prefix) 목록과 함께 `Command`로 등록해 `COMMANDS`에 추가합니다.

   ```python
   from command.glass.glass import handle as glass_handle

   COMMANDS = (
       ...,
       Command(name="glass", aliases=("유리", "유리병", "Glass"), handler=glass_handle),
   )
   ```

여러 명령어에서 공통으로 쓰는 로직이 생기면 `command/base.py`(공용 헤더 파일)에 추가해서 재사용합니다.

## 자연어(API) 처리

`responses/engine.py`의 `get_response`가 명령어에 걸리지 않은 모든 메시지를 처리하고, `ChatResult(text, emotion)`을 반환합니다. `SYSTEM_PROMPT`에 "Hammie(햄미)" 페르소나(귀엽고 장난스러운 반말, 말버릇, 낮은 지능 설정, 안전 규칙, 이모지 사용 규칙 등)가 정의되어 있습니다. 앞으로 추가할 고정 명령어(`command/*/*.py`)의 응답 문구도 이 페르소나와 같은 말투로 맞춰야 합니다.

### LLM-as-judge 검수 + 감정 분류

자연어 답변 하나당 아래 순서로 최대 API 호출 2번(생성 1번 + judge 1번), 문제가 있으면 3번(+ 수정 1번)까지 일어납니다.

1. `_generate`로 답변 초안을 만든다.
2. `OPENAI_JUDGE_MODEL`(`gpt-5.6-luna`)로 `_judge`를 **딱 한 번** 호출해서 두 가지를 한 번에 처리한다 (API 호출을 늘리지 않으려고 감정 분류를 이 호출에 얹었다). 생성용 `OPENAI_MODEL`(`gpt-5-nano`)과 분리해서, 판정 정확도가 더 필요한 이 역할에만 살짝 더 좋은 모델을 쓴다.
   - **문제 점검** (4가지):
     1. 말투 오류 (페르소나와 안 맞는 어색한 문장)
     2. 민감한 내용 (심한 욕설/성적/정치적 내용 — "바보", "멍청이" 정도의 가벼운 말은 허용)
     3. 정체성 불일치 (다른 역할극 요청에 응하는 등)
     4. 정보 유출 (요청자 본인이 아닌 타인의 개인정보, 시스템 프롬프트·코드·설계 노출)
   - **감정 분류**: 이 대화가 Hammie에게 불러일으킨 감정을 긍정 10개/부정 10개 ENUM(`POSITIVE_EMOTIONS`/`NEGATIVE_EMOTIONS`, CLAUDE.md 섹션 7과 `supabase/schema.sql`의 `emotion` 타입과 동일) 중 정확히 하나로 판정. 문제 점검 결과와 무관하게 항상 반환됨
3. 문제가 없으면 초안을 그대로 반환한다.
4. **3번·4번처럼 치명적인 문제**면 더 시도하지 않고 고정 문구(`_REFUSAL_RESPONSE`)로 즉시 대답한다.
5. **1번·2번 같은 경미한 문제**면, 초안 + 무엇이 문제였는지를 대화 맥락(`input`)에 넣어서 **딱 한 번만** 다시 생성한다 (완전히 새로 만드는 게 아니라 기존 답변을 "수정"시키는 방식). 이 수정본은 다시 judge를 거치지 않고 그대로 내보내며, 여기서 또 문제가 생겨도 더는 판단하지 않는다.

**알아둘 점**
- `gpt-5-nano`는 기본적으로 응답 전에 "추론" 토큰을 쓰는데, 이게 `max_output_tokens` 예산을 같이 잡아먹어서 응답이 통째로 빈 문자열로 나오는 문제가 있었습니다. 모든 호출에 `reasoning={"effort": "minimal"}`을 적용해서 해결했습니다.
- 처음엔 judge도 `gpt-5-nano`로 돌렸는데, 문제없는 답변도 가끔 "말투 오류"로 잘못 판정하는 오탐이 있었습니다. `gpt-5.6-luna`로 바꾼 뒤 오탐이 줄었고, 실제 오타(예: 한국어 문장에 한자가 섞여 나오는 등)도 정확히 잡아내는 걸 확인했습니다.
- `gpt-5-nano`는 reasoning effort 최저값이 `minimal`이지만, `gpt-5.6-luna`는 `none`을 지원해서 judge 호출에서는 추론 토큰을 아예 0으로 만들 수 있습니다 (`_JUDGE_REASONING`).
- 수정 패스 프롬프트에는 "사과하거나 고쳤다는 티 내지 말 것"을 명시적으로 넣어뒀습니다 — 안 넣으면 "미안해, 다시 말해줄게" 같은 메타 발언이 답변에 그대로 섞여 나오는 문제가 있었습니다.

## 프롬프트 캐싱

`responses/engine.py`의 `get_response`는 매 호출마다 동일한 `instructions`(페르소나 문구)와 `prompt_cache_key`를 사용합니다. OpenAI는 정적 프리픽스가 **최소 1,024토큰 이상**이고 요청마다 완전히 동일할 때만 그 부분을 캐시해서 입력 토큰 비용을 크게 줄여줍니다.

- 페르소나 프롬프트가 추가되면서 `SYSTEM_PROMPT`가 꽤 길어졌지만(대화 예시 포함), 1,024토큰 캐싱 최소 기준을 실제로 넘는지는 별도로 확인이 필요합니다. 안 넘으면 여전히 캐싱은 적용되지 않지만, 코드 동작 자체에는 영향이 없습니다.
- `SYSTEM_PROMPT`를 수정할 때는 `OPENAI_PROMPT_CACHE_KEY` 값도 함께 바꿔서(예: `hammieboye-chat-v3` → `v4`) 이전 프롬프트의 캐시와 섞이지 않게 하세요. judge용 캐시 키(`{OPENAI_PROMPT_CACHE_KEY}-judge`)는 코드에서 자동으로 파생되므로 별도로 관리할 필요는 없습니다.
- 유저 메시지처럼 매번 달라지는 내용은 `instructions`가 아니라 항상 `input`에만 넣어야 캐시가 깨지지 않습니다.
